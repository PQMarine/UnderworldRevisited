quote it. Look here BEFORE building a rule: if the place is already listed, it

what stands here are names and labels, never code.

## Named from more than one engine-free class

The signal for a rule implemented twice. Counted are only lines that do NOT point
somewhere else ("see", "as in", "like" and the rest of msReferenceWords) and do not
sit in an interface - otherwise every well cross-referenced rule would show up here.
A rules class together with its Unity host, a tool or a self-check is the normal
split and does not appear either.

### Look at these first

Two or more RULE classes on the same place of the original, and their pairing is
not declared as intended in msExpectedPairs. Everything here wants a look: either
the rule is written twice, or the pair belongs in that list with its reason.

None.

### Declared splits and table descriptions

the files only describes what a byte of the game's tables means (msDescribers).
